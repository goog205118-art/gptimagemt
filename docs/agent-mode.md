# 使用 Agent 模式

点击输入栏 **Agent**，旁边的设置按钮配置规划连接。默认复用当前 OpenLux 地址与生图 Key，模型为 `gpt-6.1-sol`，也可填写独立 OpenLux Key。账户余额令牌只用于查询，不参与规划。

输入栏顺序为「＋、Agent、手动」。点击模式名称切换，所选胶囊展开显示参数摘要，另一项缩短；点击展开项内的设置图标或摘要调整参数。切回手动请点击「手动」。

顶栏星芒图标打开当前会话的右侧浮窗，空闲时打开历史；浮窗的时钟图标可查看全部活动会话与记录。收起保留任务、确认表单和补问答案，停止只取消未发出的步骤。窄屏使用底部面板，开合不改变图库列宽。参考图说明与排序从「参考设置」展开。

在作品更多菜单或作品详情选择 **Agent 继续本版**，绑定当前选中的版本，而不是最新版本。该分支已确认的保留要求、精确文案和必要参考会一并继承；旧作品没有可靠记录时需核对建议保留项。结果创建新分支，原图和其他分支保留，可从详情前后对比。

## 第一次使用

1. 在 API 设置中读取可用生图模型，填写需要使用的模型 / 线路单价。
2. 打开 Agent 设置，核对规划模型 ID。可以先执行不生图的模型可见性检查。模型在清单可见不代表已验证 Responses、图片输入和结构化输出。
3. 选择每个方案最多生图请求数（1–3），填写估算费用上限，并勾选允许自动切换的候选。未勾选的模型不参与自动恢复。
4. 输入文字需求，添加参考图，提交。关键歧义通过小问题框补充，最多 2 轮，每轮最多 3 题。
5. 检查底图预览、操作、改动、保留要求、规格与估算。可以逐图调整用途和说明、精确文案、格式、背景、模型与质量。规划器或手动修改与已记录要求冲突时列出差异，需明确核对；修改条件后原核对失效。双击确认只提交一次，执行记录绑定固定方案快照。也可导入输入框转为手动编辑。

首次确认后，可以在设置开启「预算内自动执行」。只有范围、底图、参考用途、规格、单价及预算条件与上次授权一致，锁定项无冲突，素材有效时才执行。旧作品、裁切、局部和扩图仍需人工确认。没有价格或费用上限、连接变化或兼容性校验失败时需手动处理。每次进入网站默认保持手动模式。

## 操作与结果检查

- **新建**：参考图按各自用途参与创作，不自动成为编辑底图。当前服务商带图使用 `/images/edits`，确认卡会说明实际入口。
- **整图修改**：明确绑定一张底图，其他参考声明各自用途。
- **局部修改**：先在现有编辑器划选；蒙版绑定对应素材。模型将选区当作指导时不能保证精确遵循，可使用本地选区外保护。
- **本地裁切**：先预览裁切范围，拖动或方向键调整位置，再确认保存新版本；支持 PNG、JPEG、WebP，不新增生图请求。主体会被裁掉时请改用扩图。
- **扩图**：先确认方向、布局、补全内容与原图保留策略，再通过队列生成；保存原图和模型原始结果。

参考图先用 640px 预览理解整体。对小字、纹理或接口，可在确认卡选择「选取高清细节并重新规划」，划出区域后增加最长边 1024px 的高清预览，记录其所属原图和范围；这会重新发起文本规划。原始生图素材不变，预览总数最多 16 张。

结果先检查可解码性、实际尺寸、文件格式与单次返回张数；本地处理后的文件另记交付尺寸。基础检查通过不等于创作检查通过，精确文案、Logo、产品结构和选区仍标记人工核对，当前不自动运行 OCR 或视觉评审，也不因此自动重新生图。精确文字建议使用 PS 等工具后期排字。

规划失败不会自动重复请求。若 OpenLux 渠道不支持严格结构化，可手动选择 JSON 兼容模式，检查后再重试。设置中的「测试规划」会产生文本用量，不生图；不能据此认定参考图理解或真实生图能力已通过。

## 自动恢复规则

初次生成、格式修正、限流重试、线路及模型切换共用本次请求和估算费用上限。多图任务优先保留其他图的首次请求额度。

| 情况 | 行为 |
| --- | --- |
| 明确拒绝的不兼容格式参数 | 修正已识别字段，最多一次，仍计入总请求上限 |
| 明确的模型 / 线路不存在或不可用 | 在已授权、价格可估算、参数兼容的候选中先尝试同模型线路，再尝试其他模型 |
| 429 限流 | 按服务商等待时间退避，并受统一上限限制 |
| 权限、余额、内容拒绝 | 停止，不靠切换绕过 |
| 超时、断网、结果不明的 5xx | 标记结果待核实，不自动重发 |
| 已生成但下载 / 本地处理失败 | 使用已有结果，不再生图 |

执行器重新校验模型清单、提示词长度、参考图数量、蒙版、画幅、质量和格式。自动切换不删除参考图、不移除蒙版、不静默降低分辨率或质量。

费用上限只约束用户单价计算的估算值，不能保证实际账单。发生请求前预留估算，失败也不自动返还。规划的文本费用另计。留空估算上限时可以手动确认首次生成，但不自动重试。

Agent 卡片中可展开方案与执行轨迹；结果沿用现有作品卡片。可以停止后续步骤，已提交请求可能仍在服务端处理。刷新页面会停止原 Agent 自动执行，不自动恢复付费请求。失败结果的「重新生成」需要单独确认，属于新的手动请求。

## 逐张变体与执行预览

请求变体或多张候选时，AI 结合图片内容和用途给出内容类型判断、1–3 组推荐维度、推荐理由和每组 2–3 个可选细节。用户先选维度，再勾选细节；默认不勾选，未选择时不能自动生图。只选择一个细节就只生成一张，切换维度或重新规划会清空旧选择，关闭再打开保留选择与修改。推荐由规划模型生成，内容类型及理由是可核对的建议。

变体使用「讨论方向 → AI 编写完整提示词 → 用户确认 → 逐张执行」流程。Agent 会读取输入区的变化维度与各行方案；风格、幅度或保留范围不明确时可补问。用户可在「和 AI 讨论变体方向」输入偏好，点击「让 AI 调整建议」继续讨论，或选好细节后直接让 AI 编写。

「让 AI 编写 N 张提示词」只调用文本模型，不触发生图。单独的 `variants` 请求结合参考预览、类型、问答、共同简报与已选细节，返回每张完整、独立的提示词。程序直接使用对应项，不再前置共同简报、原始需求或批次汇总。主体、Logo、精确文案和保留要求保持一致，每张请求 `n=1`。逐张提示词可编辑，确认后才发送。

修改方向、选项、偏好、共同简报、参考用途或规格，会使旧的完整提示词失效，必须重新编写。修改已编写提示词会撤销确认；缺项、重复、错序或常见整批指令（包括「创作3张」）会被拦截。实际发送前还检查程序追加后的完整请求，编写失败或中断不会退回旧提示词，不自动重试。自动执行也不能越过编写与确认环节。

旧版多张方案需要重新规划；历史作品保留。转手动时使用「完整提示词 · 各行独立发送」，每行一项、每行张数为 1；原始简报不会重复拼接。精确文案放入单独字段，保留空格、大小写与换行。手动的「变化细节」模式仍可将各行差异追加到共同画面描述。

展开「程序将如何执行 · 逐张发送内容」可查看拆分请求数、每次张数、模型、尺寸、参考顺序和完整发送提示词。预览复用实际请求构建函数，包含程序追加的选区/扩图说明，不发起服务商请求。执行后，历史逐次保存任务 ID、方案版本、实际模型与入口、变体名称、提示词、状态及估算；重试和兼容回退各有记录。模型规划是建议，程序验证和实际发送有对应记录，创作效果仍由用户核对。

## 存储与当前范围

- 原始素材、方案与请求记录保存在当前浏览器；Agent Key 不进入作品备份。
- Agent Key 可选择记住，随连接配置 JSON 普通或加密导入导出。
- Agent 仅连接 OpenLux 官方地址；规划通过本站 `/api/agent` 转发到 `/v1/responses`，不提供任意地址代理。
- 原始参考用最长边 640px 的 JPEG 预览供规划使用，指定局部可追加 1024px 高清预览；实际生图使用原始素材及确认蒙版。
- 支持并行创作与有上限的自动恢复；没有离线后台任务、自动视觉打分循环、服务商任务状态查询或云端多设备同步。
- 本次开发使用模拟上游验证，没有使用之前的临时 Key，也未消耗真实文本或生图额度。实际模型 ID、Key 权限及 OpenLux 渠道兼容性需要在你的连接上验证。
